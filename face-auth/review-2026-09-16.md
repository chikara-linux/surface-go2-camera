## 2. コードレビュー

### 2-1. QML パッチ（`plasma-mobile-lockscreen-face-auth.patch`、123 行）

**`restartNoninteractive()` の入口の絞り。**

| 条件 | 理由 | 見落としがないか |
|---|---|---|
| `waitingForAuth` | PIN の判定中に会話を打ち切ると PIN の判定が失われる | 空 PIN では `waitingForAuth` が立たない（上流の仕様）。空 PIN の直後は次の `graceLockTimer.running` で拾う |
| `graceLockTimer.running` | PIN 失敗の 3 秒以内。タイマーが全部を再開するので二重にしない | 打ち切りの失敗は `onFailed` で先に捕まえるので、タイマーは動かない |
| `authenticator.unlocked` | 解錠済みなら再開しない | 数 ms の窓は R2 で塞いだ |
| 3 秒の絞り | C7（2 秒以内の失敗 4 回で認証器が死ぬ） | 打ち切りは対話型の失敗 1 回。3 秒 > 2 秒なので数えられない。利用者の PIN 失敗と重なっても 2 回止まり |

**`Idle` の判定。** `authenticator.state === ScreenLocker.Authenticators.Idle`。
`Authenticators` は `qmlRegisterUncreatableType<PamAuthenticators>("org.kde.kscreenlocker", 1, 0, "Authenticators", ...)` で
登録され、`AuthenticatorsState` は Q_ENUM（グリーターのバイナリに列挙名が
ある）。既存コードの `ScreenLocker.Authenticator.Fingerprint` と同じ形。
**万一 enum が解決できなくても壊れない**: 比較が常に偽になり打ち切り経路へ
行く。`Idle` で打ち切っても会話が無ければ失敗は来ず、1.5 秒の保険タイマーが
`startAuthenticating()` する。遅くなるだけ。実機で「screen on, idle」の
ログが一度も出なければ enum が解決できていないと分かる（§5）。

**打ち切り経路の正しさ。** ソースで追った順序:

1. `authenticator.cancel()` → `PamAuthenticator::cancel()` → ワーカーへ `cancelled`
2. ワーカーの会話関数の入れ子ループが `PAM_CONV_ERR` で抜ける → `pam_get_authtok` が
   エラー → **pam_unix は検証に入る前に `AUTH_RETURN`**（`pam_fail_delay` を呼ばない）
3. `pam_authenticate` がエラー → `Q_EMIT failed()` → その後 `m_inAuthenticate = false`
4. `PamAuthenticator` の失敗スロット: `m_failedCount` の判定（3 秒空けているので増えない）→ `failed()`
5. `PamAuthenticators` の対話型失敗ハンドラ: `setState(Idle)`、`cancelNoninteractive()`、`failed(kind=0)`
6. QML `onFailed(0)`: `noninteractiveRestartPending` が真なので「PIN が違います」を
   出さず `startNoninteractiveUnlessUnlocked()` → `startAuthenticating()`
7. `state == Idle` なので通る → 対話型 `tryUnlock()` → ワーカーへ `authenticate` を
   **キュー投入** → 非対話 `tryUnlock()` → 新しい顔認証の回

**3 と 7 の競合。** `authenticate()` は `m_inAuthenticate` が真なら即座に戻る。
3 で `failed()` を出した時点ではまだ真だが、7 の `authenticate` はワーカー
スレッドのイベントループに**キューされる**ので、いま実行中の `authenticate()`
が戻って `m_inAuthenticate = false` にしてからでないと処理されない。
競合しない。もし競合したら対話型が再プロンプトされず PIN が効かなくなる
ので、ここは重要。

**5 の `cancelNoninteractive()` が顔認証の回を殺さないか。** 顔認証が走って
いる最中に画面が点いた場合（復帰直後など）、状態は `Authenticating` なので
打ち切り経路に入る。`cancelNoninteractive()` は非対話ワーカーへも `cancelled` を
送るが、pam_howdy はプロンプトを出さない（会話待ちの入れ子ループが無い）ので
**効かない**。回は続く。7 の非対話 `tryUnlock()` は `m_inAuthenticate` が真で
戻る。結果: 対話型のプロンプトが一度張り直されるだけ。無駄だが無害。
ただし 7 の `tryUnlock()` は `m_unlocked = false` にする——回がまだ成功して
いなければ元から偽なので影響なし。成功していた場合は R2 で塞いだ。

**`tryPassword()` の変更。** `authenticator.unlocked` なら `Qt.quit()` だけ。
C++ 側の quit ハンドラが `isUnlocked()` を再確認して `_exit(0)` するので、
偽陽性でも締め出しにはならない（警告が出て何も起きない）。空 PIN の送信は
利用者の操作としては残る（触って Enter → 従来どおり認証が始まる）。

**`onDpmsTurnedOn` の置き場。** `LockScreen.qml` の既存の `DPMSUtil` ブロック。
`screen.name === Screen.name` の形は既存の `onDpmsTurnedOff` と同じ。
`lockScreenState.restartNoninteractive()` の参照も既存の
`lockScreenState.resetPassword()` と同じ解決経路。

**複数画面（USB-C で外部ディスプレイ）。** view ごとに `LockScreenState` が
あり、`authenticator` は共有。両方が打ち切りを出しても、ワーカー側の 2 つ目の
`cancelled` は入れ子ループが既に無いので効かない。失敗は 1 回、両 view の
`onFailed` が走り、`startAuthenticating()` は 1 回目だけ通る（2 回目は
`Authenticating` で無視）。それぞれの `noninteractiveRestartPending` は
自分の `onFailed` で下りる。問題なし。本機は単一画面。

**qmllint。** `--compiler disable` で error なし。新たに出る warning は
「Unqualified access」のみで、周囲の上流コードと同じ書き方
（`authenticator`、`graceLockTimer` を root 修飾なしで参照）。

### 2-2. howdy-wake.py（自己判別）

- `_lockscreen_restarts_itself()` は QML の**中身**（目印の文字列）を毎回読む。
  パッケージの版を見ないのは、実際に動いているファイルを証拠にするため。
  10KB のファイルを画面点灯のたびに読むだけで、コストは無視できる。
- **失敗の向きが安全側。** ファイルが読めない・無い → `False` → 注入する
  （＝今日の挙動）。パッチが外れたら黙って従来に戻る。
- 判定はロック中の確認のあと、復帰の見届けの前。パッチがあれば見届けも
  しない（QML が復帰時も面倒を見る）。`last_fire` は更新するので最短間隔は
  保たれる。
- `MIN_SUCCESS_DELAY` は注入の印があるときだけ働く。注入しなければ印が
  無いので、待ちは発生しない。compare.py は無改変。

### 2-3. check-install.sh / patch-watch

- `PM_BASE=6.6.5-0ubuntu0.1` は**パッチを当て直したら手で更新する定数**。
  忘れると「アーカイブに新版」が出続ける。README の手順に書いた。
- `apt-cache madison` はローカルのキャッシュを見るだけ（ネットワーク不要）。
  `apt update` が走っていなければ古いが、無いより良い。
- hold の検査は `grep -qx plasma-mobile`（完全一致）。`plasma-mobile-tweaks` の
  hold は検査していない——上書きされて困るのは本体だけ。
- `patch-watch.sh`: `sleep 20` は dpkg が status を複数回書くため。
  結果を `~/.local/state/patch-watch.last` に残し、変わったときだけ通知。
  「直った」ときも一度だけ通知する。`LC_ALL=C.UTF-8`（`C` だと日本語の
  `notify-send` が壊れる、既知の教訓）。
- `patch-watch.service` はユーザー側の oneshot。`DBUS_SESSION_BUS_ADDRESS` は
  `systemd --user` の環境にある（howdy-wake の `qdbus6` が同じ前提で動いている）。
- `PathModified=/var/lib/dpkg/status`: dpkg は `status` を rename で置き換える。
  systemd はパスの各要素を inotify で見るので rename でも拾えるはずだが、
  **実機で一度確かめる**（§5）。

### 2-4. 第 0 段（`resume_delay = 0`）

- pam_howdy は `resume_delay > 0` のときだけ印を読む。0 なら即 compare.py。
- 画面が点くまでの待ちは compare.py の `_display_comes_on(2.0)` が担う。
  **`DISPLAY_WAIT` は 2 秒未満にしてはいけない。** 画面が消えている状態で
  再開が続いたとき、却下（失敗）の間隔が 2 秒を切ると C7 で認証器が死ぬ。
  2 秒待ってから却下すれば、次の失敗は最短でも 2.5 秒後。
- 復帰時に表示が 2 秒以上遅れる機種・状況では最初の回が却下されるが、
  そのあと `dpmsTurnedOn` が再開する（状態は `Authenticating` なので打ち切り
  経路。3 秒の絞りは `lastNoninteractiveRestart = 0` から数えるので通る）。
  パッチが無い場合は howdy-wake の 5 秒の見届け → 注入が拾う。二重の保険。

## 6. 導入の順序

順序が要件。**howdy-wake を plasma-mobile より先に**（S10）。

```bash
# 0. Timeshift スナップショット
# 1. 更新保護（既存の C++ パッチも守る）
sudo apt-mark hold plasma-mobile plasma-mobile-tweaks
# 2. 第 0 段（設定は実機のものを正として再生成済み。resume_delay だけが変わる）
diff ir-face/boy-howdy/howdy/src/config.ini /etc/howdy/config.ini     # resume_delay の 1 行だけのはず
sudo install -m 644 -o root -g root ir-face/boy-howdy/howdy/src/config.ini /etc/howdy/config.ini
# 3. 保険と監視
sudo install -m 755 ir-face/src/howdy-wake.py /usr/local/bin/howdy-wake
systemctl --user restart howdy-wake.service
install -m 644 ir-face/src/patch-watch.path ir-face/src/patch-watch.service ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now patch-watch.path
# 4. 第 1・2 段（約 22 分）
plasma-mobile-patch build
plasma-mobile-patch install        # → 再ログイン
# 5. 点検
ir-face/src/check-install.sh
```

2 のあと、次の復帰から `resume_delay` の待ちが消える。3 のあと、howdy-wake は
まだ注入する（目印が無い）。4 のあと、注入をやめる。

## 7. 戻し方

| 段 | 戻す |
|---|---|
| 第 1・2 段 | `plasma-mobile-patch restore`（素の 6.6.5 に戻る）。howdy-wake は目印の消失を見て自動で注入に戻る。再ログイン |
| 第 0 段 | `/etc/howdy/config.ini` の `resume_delay = 3` |
| 保険・監視 | `systemctl --user disable --now patch-watch.path`。howdy-wake は旧版に戻す必要なし（目印が無ければ従来どおり） |
| hold | `sudo apt-mark unhold plasma-mobile plasma-mobile-tweaks` |

最悪の場合（ロック画面が出ない・PIN が効かない）: Timeshift から戻す。
その前にクイック設定のタイル（ロック画面の再起動、1 回まで）。
